# Interview Framework — Deep Dive

## Purpose

Week 6 applies Weeks 0–5 to **full designs**. This file is a **repeatable playbook** for any prompt—aligned with the [System Design Primer](https://github.com/donnemartin/system-design-primer) solutions.

## Phase B — Estimates (3–5 min)

- QPS (avg + peak)
- Storage per year
- Bandwidth if media-heavy

Reference: [week-0-orientation/0.3-back-of-envelope-math.md](../week-0-orientation/0.3-back-of-envelope-math.md)

---

## Phase C — High-level (5–10 min)

Draw:

- Client → DNS → CDN (if static/media)
- LB → App tier (stateless)
- Cache, DB, Object store, Queue

Label **read path** vs **write path**.

---

## Phase D — Core depth (10–15 min)

Interviewer picks 1–2:

- API endpoints
- Data model + indexes
- Key algorithm (hash, fan-out, ranking, crawl frontier)
- Consistency choice

---

## Phase E — Scale & failure (10–15 min)

For each bottleneck:

1. Identify it
2. Fix (cache, shard, async, replicate)
3. State **trade-off**

Cover:

- Single points of failure
- Hot keys / hot shards
- Monitoring (metrics, logs, traces)

---

## Component cheat sheet (when to mention)

| Symptom | Knob |
|---------|------|
| Read-heavy | CDN, cache, read replicas |
| Write-heavy | Sharding, queue, append log |
| Large blobs | S3 + metadata DB |
| Search | Elasticsearch / inverted index |
| Realtime feed | Fan-out on write/read hybrid |
| Global users | Multi-region, CDN, geo DNS |
| Slow async work | Message queue + workers |
