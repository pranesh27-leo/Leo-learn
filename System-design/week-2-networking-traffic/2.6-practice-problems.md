## Problem 1: DNS cutover

You move API from `203.0.113.10` to `203.0.113.50`. TTL was 86400 (24h). Users report mixed behavior for 12 hours.

**Why?** **Fix for next migration?**

<details>
<summary>Guided solution</summary>

Resolvers and clients cached old A record for up to 24h. **Fix:** Lower TTL to 60–300s **before** change; wait old TTL to pass; switch IP; verify; optionally raise TTL again. Use weighted DNS for gradual shift.

</details>

## Problem 2: CDN choice

E-commerce site: 10 MB product images, updated weekly; 1M page views/day mostly repeat visitors.

**Push or pull CDN?** **Cache strategy for JS?**

<details>
<summary>Guided solution</summary>

**Pull CDN** fine—high traffic, images reused. Weekly updates → moderate TTL + **purge on catalog update**. JS/CSS: **hash in filename** + long TTL on CDN.

</details>

## Problem 3: Load balancer design

API needs **PCI** paths (`/pay`) on hardened servers and `/browse` on general pool.

**L4 or L7?** **Why?**

<details>
<summary>Guided solution</summary>

**L7** — route by URL path/cookie. L4 cannot see HTTP path. Optional: separate subdomain `pay.example.com` to different LB target group.

</details>

## Problem 4: Reverse proxy

Startup has **one** Node server. Engineer says skip NGINX to save time.

**Give two reasons to still use reverse proxy.**

<details>
<summary>Guided solution</summary>

1. **TLS termination** and cert renewal in one place.  
2. **Rate limiting / security headers** before app.  
Bonus: gzip, static file serving, easy add second app server later.

</details>

---

## Problem 5: Microservices boundary

Team wants separate **Notification** service from **User** service.

**What data rule prevents future pain?**

<details>
<summary>Guided solution</summary>

**Notification service owns notification history DB**; User service exposes user id/email via API—**no** direct SQL joins across team databases. Duplicate display name denormalized in notifications if needed. Async events (`UserUpdated`) for sync.

</details>

---

## Problem 6: End-to-end path

User in Brazil loads `https://shop.com/home`. List components from browser to HTML (minimum 5).

<details>
<summary>Guided solution</summary>

Browser → DNS resolve → (optional CDN for static) → **LB/reverse proxy** → web/app server → cache/DB as needed → response. Mention TLS, geographic latency, edge cache for assets.

</details>
