# Object-Oriented Design (OOD) for Interviews

## What is it, in one line?

**OOD interviews** ask you to design **classes and objects** for a focused problem (parking lot, LRU cache)—complementing large-scale **system design**.

---

## Why it exists

Primer includes OOD to test **abstraction**, **encapsulation**, and **API design** at code level. Same clarity skills apply to defining service boundaries in system design.

---

## Classic problems (Primer solutions repo)

| Problem | Core skills |
|---------|-------------|
| **Hash map** | Arrays, buckets, collision handling |
| **LRU cache** | Hash map + doubly linked list, O(1) get/put |
| **Call center** | Queues, routing, agent state |
| **Deck of cards** | Enums, shuffle, deal |
| **Parking lot** | Spots, vehicles, pricing strategy |
| **Chat server** | Rooms, users, message delivery |

---

## OOD process (parallel to system design)

1. **Clarify** — rules, scale (in-memory vs distributed?), actors
2. **Entities** — nouns: `Vehicle`, `ParkingSpot`, `Ticket`
3. **Relationships** — inheritance vs composition (favor composition)
4. **Patterns** — Strategy (pricing), Factory (vehicle types), Observer (notifications)
5. **APIs** — public methods on key classes

---

## Example sketch: LRU Cache

**Requirements:** `get(key)`, `put(key, value)`, evict least recently used at capacity.

**Classes:**

- `LRUCache` — `capacity`, `get`, `put`
- Internal: `HashMap<Key, Node>` + doubly linked list for order

**Real-world link:** Redis approximates LRU eviction; Memcached slab LRU—same concept at datacenter scale.

---

## Example sketch: Parking lot

**Entities:** `ParkingLot`, `Level`, `Spot`, `Vehicle` (Car, Truck), `Ticket`, `PaymentService`.

**Methods:** `park(vehicle) → ticket`, `exit(ticket) → fee`, `findSpot(vehicleType)`.

**Extensions:** Electric spots, handicap, concurrent park (locks).

---

## OOD vs system design

| OOD | System design |
|-----|----------------|
| Classes in one process | Services across network |
| Minutes of data | Petabytes, years retention |
| Threads/locks | Queues, sharding, CAP |

Interview may include **both** rounds in one loop.

---

## Interview tips

- Start with **interfaces** for extensibility.
- Mention **single responsibility**—small classes.
- If asked “scale this,” bridge to system design: “LRU cache becomes Redis cluster with consistent hashing.”

---

## Recap

- OOD = entities, relationships, patterns for bounded problems.
- Practice Primer list: hash map, LRU, parking lot, chat.
- Connects to microservice boundaries in large designs.
