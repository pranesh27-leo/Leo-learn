# RPC and REST

## What is it, in one line?

**RPC** exposes **remote procedures** (actions); **REST** exposes **resources** (nouns) manipulated with HTTP verbs.

---

## Why it exists

**Internal microservices** often want typed, efficient calls (**gRPC/Protobuf**). **Public APIs** want simple HTTP JSON and cache-friendly URLs (**REST**).

---

## RPC (Primer)

Client calls `getUser(123)`; stub **marshals** args over network; server unmarshals and executes.

**Pros:** Performance, strong contracts (Protobuf), good for internal east-west traffic.  
**Cons:** Tight coupling; new operation = new RPC; harder to cache at HTTP cache layers.

**Frameworks:** gRPC, Apache Thrift, Avro.

**Real-world:** Google internal Stubby/gRPC between services.

---

## REST (Primer)

- **Resources** identified by URI (`/persons/123`)
- **Verbs** HTTP (GET, POST, PUT, DELETE)
- **Stateless** — each request self-contained
- **Cacheable** responses when marked

**Pros:** Loose coupling, browser-friendly, standard HTTP tooling, scales with partitions.  
**Cons:** Chatty nested resources; awkward for non-CRUD actions; response bloat over time.

**Real-world:** Stripe API—RESTful resources for charges, customers, webhooks.

---

## Comparison (Primer table simplified)

| Operation | RPC style | REST style |
|-----------|-----------|------------|
| Sign up | POST /signup | POST /persons |
| Get user | GET /readPerson?id=123 | GET /persons/123 |
| Delete user | POST /removeUser | DELETE /persons/123 |

---

## When to use which

| Context | Typical choice |
|---------|----------------|
| Public mobile/web API | REST or GraphQL |
| Internal service mesh | gRPC |
| Browser direct | REST (gRPC-web limited) |
| Streaming events | WebSockets, SSE, or Kafka—not classic REST |

**GraphQL** (bonus): client specifies fields—reduces over-fetch for mobile; adds server complexity.

---

## Interview questions

- “REST vs RPC for 50 microservices?” — Often gRPC internal + REST gateway external.
- “Design idempotent POST?” — Idempotency-Key header stored with result.

---

## Recap

- RPC = actions, performance, contracts.
- REST = resources, HTTP, public APIs.
- Many systems use **both**.
