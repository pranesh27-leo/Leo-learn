# Intervals and Merge Patterns

## What is it, in one line?

Sort intervals by **start time** (or end time), then sweep through them once to merge overlaps, count rooms, or find gaps.

---

## Why it exists

Any time you have ranges — meetings, IP address blocks, DNA segments, stock price windows, video ads, database row ranges — you need to answer: "Do these overlap?" "How many overlap at once?" "Where are the gaps?"

The interval pattern turns a 2D problem (each interval has two coordinates) into a 1D sweep by sorting on one dimension.

---

## Interval Representation

```cpp
// Each interval: [start, end), or [start, end] depending on the problem
vector<vector<int>> intervals = {{0, 3}, {1, 4}, {5, 7}, {6, 9}};
// Visualized:
// [0---------3]
//     [1---------4]
//                 [5-----7]
//                   [6---------9]
```

**Critical first step:** Always sort by start time. This is the single most important decision in interval problems.

```cpp
sort(intervals.begin(), intervals.end()); // sorts by first element (start time)
```

## Pattern 1: Merge Overlapping Intervals (LC 56)

**Problem:** Given a list of intervals, merge all overlapping ones.

**Algorithm:** After sorting by start time, maintain a `result` list. For each interval:
- If it overlaps with the last interval in `result` (i.e., `interval.start <= result.back().end`), merge them by extending the end.
- Otherwise, add it as a new interval.

```cpp
vector<vector<int>> merge(vector<vector<int>>& intervals) {
    if (intervals.empty()) return {};

    sort(intervals.begin(), intervals.end()); // sort by start time

    vector<vector<int>> result;
    result.push_back(intervals[0]);

    for (int i = 1; i < intervals.size(); i++) {
        if (intervals[i][0] <= result.back()[1]) {
            // Overlapping: extend the end of the current merged interval
            result.back()[1] = max(result.back()[1], intervals[i][1]);
        } else {
            // Non-overlapping: add a new interval
            result.push_back(intervals[i]);
        }
    }
    return result;
}
```

**Complexity:** O(n log n) for sorting, O(n) for the sweep. Total: O(n log n).

**Why sorting by start time works:** After sorting, intervals arrive in order. If interval[i] overlaps with interval[i-1], it must also be the case that `intervals[i].start <= intervals[i-1].end` — because `intervals[i].start >= intervals[i-1].start` (they're sorted). So we only need to check one condition, not compare against all previous intervals.

## Pattern 2: Non-overlapping Intervals (LC 435)

**Problem:** Remove the minimum number of intervals so that the rest don't overlap.

**Algorithm (greedy):** Sort by **end time** (not start time). Greedily keep intervals that end earliest — they leave the most room for future intervals.

```cpp
int eraseOverlapIntervals(vector<vector<int>>& intervals) {
    if (intervals.empty()) return 0;

    // Sort by END time — this is the key insight
    sort(intervals.begin(), intervals.end(), [](const auto& a, const auto& b) {
        return a[1] < b[1];
    });

    int kept = 1; // always keep the first one (earliest ending)
    int lastEnd = intervals[0][1];

    for (int i = 1; i < intervals.size(); i++) {
        if (intervals[i][0] >= lastEnd) {
            // This interval doesn't overlap with the last kept one
            kept++;
            lastEnd = intervals[i][1];
        }
        // Otherwise: skip this interval (remove it)
    }

    return intervals.size() - kept; // removed = total - kept
}
```

**Why sort by end time, not start time?** When you have a choice between two non-overlapping intervals, the one that ends earlier leaves more room for subsequent intervals. This greedy choice is optimal — you can prove it with an exchange argument (see Week 5.3).

## Pattern 3: Meeting Rooms (LC 253) — Minimum Number of Rooms

**Problem:** Given meeting times, find the minimum number of conference rooms needed.

**Algorithm:** Sort by start time. Use a **min-heap** of end times. For each meeting:
- If the earliest-ending meeting has ended (`heap.top() <= meeting.start`), reuse that room (pop from heap).
- Push the current meeting's end time onto the heap.
- The heap size at the end = minimum rooms needed.

```cpp
int minMeetingRooms(vector<vector<int>>& intervals) {
    if (intervals.empty()) return 0;

    sort(intervals.begin(), intervals.end()); // sort by start time

    priority_queue<int, vector<int>, greater<int>> minHeap; // min-heap of end times

    for (auto& interval : intervals) {
        // If the earliest meeting has ended, reuse that room
        if (!minHeap.empty() && minHeap.top() <= interval[0]) {
            minHeap.pop();
        }
        // Schedule this meeting (either new room or reused room)
        minHeap.push(interval[1]);
    }

    return minHeap.size();
}
```

**Complexity:** O(n log n) for sorting + O(n log n) for heap operations. Total: O(n log n).

**Connection to other topics:** This uses a heap (Week 3.3) and sorting (this week). The heap tracks "how many meetings are currently active" — the size is the answer.

## Pattern 4: Insert Interval (LC 57)

**Problem:** Given a sorted list of non-overlapping intervals and a new interval, insert and merge as needed.

**Algorithm:** Three phases — before, overlapping, after.

```cpp
vector<vector<int>> insert(vector<vector<int>>& intervals, vector<int>& newInterval) {
    vector<vector<int>> result;
    int i = 0, n = intervals.size();

    // Phase 1: Add all intervals that end before newInterval starts (no overlap)
    while (i < n && intervals[i][1] < newInterval[0]) {
        result.push_back(intervals[i++]);
    }

    // Phase 2: Merge all overlapping intervals into newInterval
    while (i < n && intervals[i][0] <= newInterval[1]) {
        newInterval[0] = min(newInterval[0], intervals[i][0]);
        newInterval[1] = max(newInterval[1], intervals[i][1]);
        i++;
    }
    result.push_back(newInterval);

    // Phase 3: Add all remaining intervals (no overlap)
    while (i < n) {
        result.push_back(intervals[i++]);
    }

    return result;
}
```

**Complexity:** O(n) — one pass through the list (already sorted).

## Pattern 5: Sweep Line with Events

When you need to count **maximum overlap at any point**, or find gaps, convert each interval into two events:

```
Interval [start, end] → event(start, +1) and event(end, -1)
```

Sort events by time (ties: process +1 before -1, or vice versa depending on whether the interval is inclusive).

```cpp
// Find maximum number of overlapping intervals at any point
int maxOverlap(const vector<vector<int>>& intervals) {
    vector<pair<int, int>> events;
    for (auto& iv : intervals) {
        events.push_back({iv[0], 1});  // start: +1
        events.push_back({iv[1], -1}); // end: -1
    }
    sort(events.begin(), events.end());

    int maxConcurrent = 0, current = 0;
    for (auto& [time, type] : events) {
        current += type;
        maxConcurrent = max(maxConcurrent, current);
    }
    return maxConcurrent;
}
```

## Common Mistakes

| Mistake | What happens | Fix |
|---------|-------------|-----|
| Sorting by end time for merge | Doesn't work — you need start time to detect overlaps | Sort by start time for merge; end time for "minimum removals" |
| Not handling adjacent intervals `[1,2], [2,3]` | May merge or not depending on the problem | Check problem statement: is `[1,2]` and `[2,3]` overlapping? Usually yes if `end >= start` |
| Modifying the result list while iterating | Segfault or incorrect behavior | Build a new result list; don't modify in place |
| Not sorting at all | O(n²) pairwise comparison — works but slow | Sort first, sweep once: O(n log n) |

---

## The Pattern Decision

| Problem asks for… | Sort by… | Then… |
|-------------------|----------|-------|
| Merge overlaps | Start time | Sweep, extend `back().end` when overlapping |
| Minimum removals | **End time** | Greedily keep earliest-ending |
| Minimum rooms | Start time | Min-heap of end times |
| Maximum overlap | N/A (event-based) | Two events per interval, sweep |
| Insert into sorted | Already sorted | Three phases: before, merge, after |
| Find gaps | Start time | Sweep, record gap when `next.start > current.end` |

---

## Recap

- **Sort intervals by start time** as the default first step.
- **Merge:** sweep and extend `back().end` when `interval.start <= back.end`.
- **Minimum rooms:** min-heap of end times; heap size = answer.
- **Minimum removals:** sort by **end time**, greedily keep earliest-ending.
- **Sweep line:** convert to events, sort by time, track running count.
- These patterns show up in calendar apps, resource allocation, stock analysis, and DNA analysis.
