# Graph Representations, BFS, and DFS

Hello Algo **Ch 9**: [Graph](https://www.hello-algo.com/en/chapter_graph/graph/), [Graph traversal](https://www.hello-algo.com/en/chapter_graph/graph_traversal/).

## What is it, in one line?

A **graph** is a collection of nodes (vertices) connected by edges (relationships). **BFS** explores by distance from a start node; **DFS** explores by going as deep as possible along each branch before backtracking.

---

## Why it exists

Almost every real system is a graph: social networks (friends), road maps (intersections + roads), web pages (hyperlinks), task dependencies (build systems), microservices (API calls), database foreign keys (referential integrity).

When your data has **relationships** rather than just a linear or hierarchical order, you need graph algorithms.

**Real-world:** LinkedIn's "2nd degree connection" feature is BFS. Your build system detecting circular dependencies is DFS. Package managers resolving `npm install` are topological sorts on a dependency graph.

---

## Graph Terminology

| Term | Meaning | Example |
|------|---------|---------|
| **Vertex (node)** | A point/entity | A person, a server, a city |
| **Edge** | A connection between two vertices | "A is friends with B", "road from X to Y" |
| **Directed** | Edge has a one-way direction | Twitter follows (A follows B ≠ B follows A) |
| **Undirected** | Edge goes both ways | Facebook friends, road networks |
| **Weighted** | Each edge has a cost/value | Flight durations, network latency |
| **Degree** | Number of edges touching a vertex | How many friends you have |
| **Path** | Sequence of connected vertices | A → B → C → D |
| **Cycle** | A path that returns to its start | A → B → C → A |
| **Connected** | You can reach every node from every other | One single network, not two isolated ones |
| **DAG** | Directed Acyclic Graph — directed, no cycles | Task dependencies, build systems |

## Representations — two main choices

### Adjacency List

A `vector` (or hash map) where each vertex points to a list of its neighbors.

```cpp
// For an undirected graph with n vertices:
vector<vector<int>> adj(n);

// Add edge between 0 and 1 (undirected = both directions):
adj[0].push_back(1);
adj[1].push_back(0);
```

**Space:** O(V + E) — you store each edge once (undirected) or twice.
**Time to find neighbors of vertex u:** O(degree of u).
**Best for:** Sparse graphs (far fewer edges than V²). This is the default in interviews and in production (network topology, social graphs, web links).

**Weighted variant:**
```cpp
vector<vector<pair<int, int>>> adj(n); // pair = {neighbor, weight}
adj[0].push_back({1, 5}); // edge 0→1 with weight 5
```

### Adjacency Matrix

A 2D array where `matrix[i][j]` = 1 (or the weight) if an edge exists between i and j, 0 otherwise.

```cpp
vector<vector<int>> matrix(n, vector<int>(n, 0));
matrix[0][1] = 1; // edge between 0 and 1
```

**Space:** O(V²) — always, even if you have zero edges.
**Time to check if edge (u, v) exists:** O(1).
**Best for:** Dense graphs (E ≈ V²) or when you need O(1) edge lookup. Rarely the answer in interviews unless V ≤ 1,000 and density is high.

### Which to choose?

| Factor | Adjacency List | Adjacency Matrix |
|--------|---------------|-----------------|
| Memory | O(V + E) — compact | O(V²) — wasteful for sparse |
| "Neighbors of u?" | O(degree of u) | O(V) — scan row |
| "Is edge (u,v)?" | O(degree of u) | **O(1)** |
| Interview default | ✅ Almost always | Rarely |

## BFS — Breadth-First Search

**Idea:** Explore level by level. Visit all neighbors of the start node, then all neighbors of those neighbors, and so on. Uses a **queue** (FIFO).

### Why BFS? Three reasons:
1. **Shortest path in unweighted graphs** — BFS visits nodes in order of increasing distance from start. When you first reach a node, you found the shortest path to it.
2. **Layer-by-layer exploration** — "Who are all my friends?" then "Who are all my friends' friends?"
3. **Connectivity check** — "Can I reach node B from node A?"

### The algorithm

```cpp
#include <queue>
#include <vector>

// Return the shortest distance from start to end, or -1 if unreachable
int bfsDistance(int start, int end, const vector<vector<int>>& adj) {
    int n = adj.size();
    vector<bool> visited(n, false);
    queue<pair<int, int>> q; // {vertex, distance}

    q.push({start, 0});
    visited[start] = true;

    while (!q.empty()) {
        auto [u, dist] = q.front();
        q.pop();

        if (u == end) return dist; // first time we see end = shortest path

        for (int v : adj[u]) {
            if (!visited[v]) {
                visited[v] = true;
                q.push({v, dist + 1});
            }
        }
    }
    return -1; // unreachable
}
```

### Complexity

| Metric | Value |
|--------|-------|
| **Time** | O(V + E) — every vertex enqueued at most once, every edge examined at most once |
| **Space** | O(V) — the queue holds at most one level's worth of vertices |

### Critical insight: why BFS gives shortest path

BFS explores in "rings" around the start node:
- Ring 0: start node itself (distance 0)
- Ring 1: all direct neighbors (distance 1)
- Ring 2: all neighbors of ring 1 nodes (distance 2)
- ...

Because the queue is FIFO, you always process distance-d nodes before distance-(d+1) nodes. Therefore **the first time you reach any node, it is via the shortest path**. DFS doesn't have this guarantee — it can wander down a long branch and reach the target at distance 100 when a path of distance 2 existed.

**When this guarantee breaks:** When edges have different weights. BFS assumes every edge costs 1. For weighted shortest path, you need Dijkstra's algorithm (beyond this week's scope).

### Tracing BFS by hand

```
Graph:   0 -- 1 -- 2
          |    |
          3 -- 4

BFS from 0:
Queue operations:
  push(0)        → queue: [0]
  pop(0), push(1,3)  → queue: [1, 3]    (visit neighbors of 0)
  pop(1), push(2,4)  → queue: [3, 2, 4] (visit neighbors of 1; 0 already visited)
  pop(3)           → queue: [2, 4]      (neighbors of 3: 0 and 4, both visited)
  pop(2)           → queue: [4]
  pop(4)           → queue: []          (all neighbors visited)

Visit order: 0 → 1 → 3 → 2 → 4
Distances:   0:0, 1:1, 3:1, 2:2, 4:2
```

## DFS — Depth-First Search

**Idea:** Go as deep as possible along one path before backtracking. Uses **recursion** (or an explicit stack).

### Why DFS? Three reasons:
1. **Cycle detection** — if you encounter a visited node that's still on your current path (in the "recursion stack"), you found a cycle.
2. **Topological sort** — processing nodes in reverse finish-order gives a valid dependency ordering (see 4.3).
3. **Connected components** — one DFS call from any unvisited node visits exactly one component.

### The algorithm (recursive)

```cpp
void dfs(int u, int parent,
         vector<bool>& visited,
         const vector<vector<int>>& adj) {
    visited[u] = true;
    for (int v : adj[u]) {
        if (v == parent) continue; // don't go back the way we came (undirected)
        if (visited[v]) {
            // v is already visited and not our parent → cycle exists!
            // Handle cycle detection here
            continue;
        }
        dfs(v, u, visited, adj);
    }
}
```

### The algorithm (iterative, explicit stack)

```cpp
void dfsIterative(int start, const vector<vector<int>>& adj) {
    vector<bool> visited(adj.size(), false);
    stack<int> st;

    st.push(start);
    while (!st.empty()) {
        int u = st.top();
        st.pop();
        if (visited[u]) continue;
        visited[u] = true;
        // Process u here (e.g., print it)

        for (int v : adj[u]) {
            if (!visited[v]) st.push(v);
        }
    }
}
```

### Complexity

| Metric | Value |
|--------|-------|
| **Time** | O(V + E) — same as BFS: visit each vertex and edge once |
| **Space** | O(V) — recursion stack depth = tree height (worst case O(V) for a line graph) |

### BFS vs DFS — when to use which

| You need… | Use |
|-----------|-----|
| Shortest path (unweighted) | **BFS** — guaranteed |
| "Is there ANY path?" | Either, but BFS finds shorter ones first |
| Cycle detection | **DFS** — recursion stack tells you |
| Connected components | Either |
| Topological sort | **DFS** (reverse post-order) or BFS (Kahn's algorithm) |
| Flood fill / "paint bucket" | Either, but DFS is simpler to code |
| Maze solving (shortest route) | **BFS** — DFS gives *a* path, not the *shortest* |

## Number of Islands (LC 200) — the canonical grid graph

Given a 2D grid of `'1'` (land) and `'0'` (water), count the number of islands (connected land cells).

**Key insight:** The grid *is* a graph. Each land cell is a vertex; edges go up, down, left, right to adjacent land cells. Counting islands = counting connected components.

```cpp
int numIslands(vector<vector<char>>& grid) {
    int rows = grid.size(), cols = grid[0].size();
    int count = 0;
    vector<vector<bool>> visited(rows, vector<bool>(cols, false));
    const int dr[4] = {-1, 1, 0, 0}; // up, down, left, right
    const int dc[4] = {0, 0, -1, 1};

    auto dfs = [&](auto&& self, int r, int c) {
        visited[r][c] = true;
        for (int d = 0; d < 4; d++) {
            int nr = r + dr[d], nc = c + dc[d];
            if (nr >= 0 && nr < rows && nc >= 0 && nc < cols &&
                grid[nr][nc] == '1' && !visited[nr][nc]) {
                self(self, nr, nc); // recursive call
            }
        }
    };

    for (int r = 0; r < rows; r++)
        for (int c = 0; c < cols; c++)
            if (grid[r][c] == '1' && !visited[r][c]) {
                dfs(dfs, r, c); // sink this entire island
                count++;
            }

    return count;
}
```

**Complexity:** O(rows × cols) — each cell visited at most once. O(rows × cols) space for `visited` (or modify grid in-place to save space).

**Why this matters:** Grid → graph is one of the most common interview transformations. Same technique applies to "surrounded regions" (LC 130), "wall and gates" (LC 329), and flood-fill problems.

## Common Mistakes

| Mistake | What happens | Fix |
|---------|-------------|-----|
| Forgetting `visited` array in BFS | Infinite loop on cycles | Mark when you **enqueue**, not when you dequeue |
| Not handling disconnected graphs | Only one component explored | Wrap BFS/DFS in a loop over all vertices |
| BFS on weighted graph for shortest path | Wrong answer | Use Dijkstra (weighted) or ensure all weights are equal |
| DFS recursion depth overflow on large graphs | Stack overflow crash | Use iterative DFS with explicit stack |
| Counting edges twice in undirected graph | Wrong component count | Check `v != parent` or use `visited` |

---

## Interview Tips

1. **First question to ask:** "Is the graph directed or undirected? Weighted or unweighted?" The answer determines whether BFS gives shortest paths and whether you need Dijkstra.

2. **Grid problems:** Always check — is this actually a graph? If you're exploring adjacent cells, yes. Define the 4 directions array once: `dr[4] = {-1, 1, 0, 0}`, `dc[4] = {0, 0, -1, 1}`.

3. **"How are A and B connected?"** → BFS from A until you find B, recording the parent of each node. Then trace back from B to A.

4. **State the invariant:** For BFS — "visited when enqueued, so the queue contains the frontier of the current ring." For DFS — "the recursion stack contains exactly the current path from root to the node being explored."

---

## Recap

- **Graph** = nodes + edges. Two representations: adjacency list (O(V+E), interview default) and adjacency matrix (O(V²), fast edge lookup).
- **BFS** (queue) = shortest path on unweighted graphs, level-by-level. O(V+E) time.
- **DFS** (recursion/stack) = cycle detection, connected components, topological sort. O(V+E) time.
- Grid problems → graph problems. Each cell is a vertex; adjacent cells are edges.
- Master: BFS distance, DFS cycle detection, number of islands.
