# Sorting Algorithms — and When They Actually Matter

Hello Algo **Ch 11**: [Sorting](https://www.hello-algo.com/en/chapter_sorting/sorting_algorithm/).

## What is it, in one line?

**Sorting** arranges elements in order. In interviews you rarely implement a full sort — you need to know **which algorithm to reach for, why, and what properties it has** (stable? in-place? parallelizable?).

---

## Why it exists

Sorting is the single most common preprocessing step in real systems: database indexes (B-trees keep data sorted), merge operations, "top K" queries, range searches, deduplication, and the foundation of nearly every analytics pipeline.

In interviews, sorting is often the **enabler** — you sort first, then a linear scan solves the problem that seemed hard.

---

## The Big Three — understand these

### Merge Sort — O(n log n) guaranteed, stable, not in-place

**How it works:** Divide the array in half, recursively sort each half, then merge the two sorted halves. The merge step is linear: compare the heads of both halves, take the smaller, repeat.

```cpp
void mergeSort(vector<int>& arr, int left, int right) {
    if (left >= right) return;
    int mid = left + (right - left) / 2;
    mergeSort(arr, left, mid);
    mergeSort(arr, mid + 1, right);

    // Merge the two sorted halves
    vector<int> temp;
    int i = left, j = mid + 1;
    while (i <= mid && j <= right) {
        if (arr[i] <= arr[j]) temp.push_back(arr[i++]); // <= makes it stable
        else temp.push_back(arr[j++]);
    }
    while (i <= mid) temp.push_back(arr[i++]);
    while (j <= right) temp.push_back(arr[j++]);
    copy(temp.begin(), temp.end(), arr.begin() + left);
}
```

**Key properties:**
- **Stable:** equal elements preserve their original order (the `<=` above, not `<`). This matters when you sort by one field then another — the second sort's stability preserves the first sort's ordering.
- **Not in-place:** requires O(n) extra space for the temporary array.
- **Divide and conquer:** the pattern from 5.1 applied to sorting.
- **Best for:** linked lists (where merging is O(1) with pointer manipulation), external sorting (data larger than RAM), and when stability is required.

### Quick Sort — O(n log n) average, in-place, unstable

**How it works:** Pick a "pivot" element. Partition the array so everything smaller goes left, everything larger goes right. Recurse on both sides.

```cpp
void quickSort(vector<int>& arr, int left, int right) {
    if (left >= right) return;

    // Choose pivot (last element for simplicity; randomized is better in practice)
    int pivot = arr[right];
    int i = left; // i is the boundary: arr[left..i-1] < pivot

    for (int j = left; j < right; j++) {
        if (arr[j] <= pivot) {
            swap(arr[i], arr[j]);
            i++;
        }
    }
    swap(arr[i], arr[right]); // pivot now in its final position
    quickSort(arr, left, i - 1);
    quickSort(arr, i + 1, right);
}
```

**Key properties:**
- **In-place:** O(log n) stack space only (the recursion depth).
- **Unstable:** equal elements may reorder.
- **Average case:** O(n log n). **Worst case:** O(n²) when the pivot is always the smallest or largest (already-sorted input with bad pivot choice).
- **C++'s `std::sort`** uses a hybrid: introsort = quicksort → switches to heapsort if recursion depth exceeds 2·log(n), guaranteeing O(n log n) worst case.

**Why it's usually fastest in practice:**
1. Excellent cache locality — scans the array sequentially
2. No extra memory allocation
3. Small constant factors
4. Modern CPUs love the predictable access pattern

### Heap Sort — O(n log n) worst case, in-place, unstable

**How it works:** Build a max-heap from the array. Repeatedly extract the max (swap root with last element, shrink heap, heapify down). Each extraction is O(log n), done n times.

**Key properties:**
- **Guaranteed O(n log n)** even in the worst case.
- **In-place:** O(1) extra space.
- **Poor cache performance:** jumps around the array (parent ↔ child indices).
- **Rarely the default** in production sort implementations, but important for understanding priority queues (Week 3.3).

### Comparison table

| Algorithm | Avg time | Worst time | Space | Stable? | In-place? |
|-----------|----------|------------|-------|---------|-----------|
| **Merge sort** | O(n log n) | O(n log n) | O(n) | ✅ | ❌ |
| **Quick sort** | O(n log n) | O(n²) | O(log n) | ❌ | ✅ |
| **Heap sort** | O(n log n) | O(n log n) | O(1) | ❌ | ✅ |
| **Counting sort** | O(n + k) | O(n + k) | O(k) | ✅ | ❌ |

## The Interview-Useful Ones

### Counting Sort — O(n) when values are small integers

**When to use:** The input values are integers in a known small range [0, k] where k ≈ n.

**How it works:** Count occurrences of each value, then reconstruct the sorted array from the counts.

```cpp
vector<int> countingSort(const vector<int>& arr, int maxVal) {
    vector<int> count(maxVal + 1, 0);
    for (int x : arr) count[x]++;

    vector<int> result;
    result.reserve(arr.size());
    for (int val = 0; val <= maxVal; val++)
        for (int c = 0; c < count[val]; c++)
            result.push_back(val);
    return result;
}
```

**Real-world:** Sorting grades (0–100), counting sort inside radix sort, frequency analysis.

### Why you should NOT implement bubble sort / insertion sort in interviews

These are O(n²) algorithms. Insertion sort is useful when the array is "nearly sorted" (O(n) best case) and for tiny inputs (< 20 elements), but unless the problem specifically asks for it, reach for a comparison sort or mention it as an optimization inside quicksort (switch to insertion sort when subarray is small).

## Stability — the property everyone forgets until it bites

**Stable sort:** if two elements are equal, their relative order is preserved.

```
Before:  (A, 3) (B, 1) (C, 3) (D, 2)
Sort by value (stable):  (B, 1) (D, 2) (A, 3) (C, 3)  ← A still before C
Sort by value (unstable): (B, 1) (D, 2) (C, 3) (A, 3) ← order swapped
```

**When stability matters:** Multi-key sorting. Sort by department (asc), then by salary (desc). If the salary sort is stable, department order is preserved within equal salaries. If not, department order is scrambled.

**Interview question that tests this:** "Sort a CSV by multiple columns with different directions" — this is exactly the stability test, and it's the real-world project for this topic in `PATTERN-PROJECTS.md`.

## External Sort — data larger than RAM

When the dataset is gigabytes and your RAM is megabytes, you can't load it all. The algorithm:

1. **Divide:** Split the file into chunks that fit in memory.
2. **Sort:** Sort each chunk in memory (using quicksort or merge sort).
3. **Write:** Write each sorted chunk to a temporary file.
4. **Merge:** K-way merge the sorted chunks using a **min-heap** of size K (one element from each chunk). Output the merged result.

```
5GB file, 1GB RAM:
  → 5 chunks of 1GB each, sorted
  → 5-way merge using min-heap of size 5
  → One sorted 5GB output
```

**Time:** O(n log n) total. **Space:** O(k) for the heap where k = number of chunks.

This connects directly to the D&C external sorter project in `PATTERN-PROJECTS.md` and to Week 3 (heap).

## The "Sort First" Pattern

Many interview problems are "sort, then scan in one pass":

| Problem | Sort by | Then what? |
|---------|---------|------------|
| "Merge overlapping intervals" (LC 56) | Start time | Linear scan, merge as you go |
| "Meeting rooms" (LC 253) | Start time | Sweep with a min-heap of end times |
| "Contains duplicate" (LC 217) | Value | Adjacent elements must be equal if duplicate exists |
| "H-index" (LC 274) | Citations descending | Find the largest h where h papers have ≥ h citations |
| "Kth largest element" | Any (or use quickselect) | Pick index n-k |
| "Task scheduler" (LC 621) | Frequency descending | Greedy assignment |

**The pattern:** Sorting transforms a problem from "search in 2D space" to "scan a 1D line." The O(n log n) cost of sorting is amortized over the entire problem.

## Common Mistakes

| Mistake | What happens | Fix |
|---------|-------------|-----|
| Using `sort()` without a custom comparator for structs | Sorts by first member only | `sort(v.begin(), v.end(), [](const A& a, const A& b){ return a.field < b.field; });` |
| Not handling equal elements in comparator | Undefined behavior in C++ (strict weak ordering violated) | Use `<=` carefully; comparator must return `false` for equal elements: `[](a, b){ return a.val < b.val; }` |
| Assuming `std::sort` is stable | It isn't — it's introsort | Use `std::stable_sort` when order of equals matters |
| Off-by-one in merge sort boundaries | Missing elements or infinite recursion | `mid = left + (right - left) / 2`, recurse on `[left, mid]` and `[mid+1, right]` |

---

## Recap

- **Merge sort:** stable, O(n log n) guaranteed, O(n) space. Foundation of D&C.
- **Quick sort:** in-place, O(n log n) average, fastest in practice. `std::sort`'s core.
- **Heap sort:** worst-case O(n log n), in-place, poor cache behavior.
- **Counting sort:** O(n) for small integer range. Stable.
- **Stability matters** for multi-key sorting — merge sort and counting sort are stable.
- **Sort-first pattern:** sort the input, then a linear scan solves problems that seemed 2D.
- **External sort:** divide → sort chunks in memory → k-way merge with a heap.
