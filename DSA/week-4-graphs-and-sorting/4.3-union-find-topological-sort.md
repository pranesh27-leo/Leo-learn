# Union-Find and Topological Sort

## What is it, in one line?

**Union-Find** (Disjoint Set Union) tracks which elements belong to which group as groups are merged over time. **Topological sort** orders tasks so that every dependency comes before the task that needs it.

---

## Union-Find — tracking connected components dynamically

### Why it exists

Imagine you're building a network monitor. Links between servers come online and go offline. You need to answer: "Can server A reach server B?" **Right now**, not at the end.

BFS/DFS would give you the answer, but each query costs O(V + E). With 100,000 servers and 10,000 queries, that's millions of operations per query.

Union-Find answers "are these two in the same group?" in **near O(1)** — literally O(α(n)) where α is the inverse Ackermann function, which is ≤ 4 for any input size that fits in the observable universe.

### Real-world use cases

- **Network partition detection** — are these two nodes in the same cluster?
- **Kruskal's MST algorithm** — "would adding this edge create a cycle?" (two endpoints already in the same set → cycle)
- **Image segmentation** — which pixels are connected?
- **Duplicate account merging** — "these three email addresses belong to the same person"
- **Connected components in an undirected graph** — count distinct groups

### The data structure

Each element starts in its own set. Two operations:

| Operation | Meaning |
|-----------|---------|
| `find(x)` | Which set does x belong to? (returns the representative/root of x's set) |
| `unite(a, b)` | Merge the sets containing a and b |

### Basic implementation (naive — O(n) per operation)

```cpp
struct DSU {
    vector<int> parent;
    DSU(int n) : parent(n) {
        iota(parent.begin(), parent.end(), 0); // parent[i] = i
    }
    int find(int x) {
        while (x != parent[x]) x = parent[x]; // walk up to root
        return x;
    }
    void unite(int a, int b) {
        parent[find(a)] = find(b); // make root of a point to root of b
    }
};
```

**Problem:** Without optimizations, the tree can become a chain (depth = n), making `find()` O(n). You've just turned your "near O(1)" structure into a linked list.

### Optimization 1: Path Compression

When you call `find(x)`, make every node on the path point directly to the root. This flattens the tree.

```cpp
int find(int x) {
    if (parent[x] != x)
        parent[x] = find(parent[x]); // path compression: skip intermediate nodes
    return parent[x];
}
```

After one `find()` on a deep chain, the entire chain points to the root. Subsequent calls are O(1).

### Optimization 2: Union by Rank

When merging two trees, always attach the shorter tree under the taller one. This keeps trees shallow.

```cpp
struct DSU {
    vector<int> parent, rank;
    DSU(int n) : parent(n), rank(n, 0) {
        iota(parent.begin(), parent.end(), 0);
    }
    int find(int x) {
        if (parent[x] != x)
            parent[x] = find(parent[x]);
        return parent[x];
    }
    void unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return; // already in the same set

        // Union by rank: attach shorter tree under taller
        if (rank[a] < rank[b]) swap(a, b);
        parent[b] = a;
        if (rank[a] == rank[b]) rank[a]++;
    }
    bool same(int a, int b) {
        return find(a) == find(b);
    }
};
```

### With both optimizations: O(α(n))

Path compression + union by rank together give O(α(n)) amortized per operation. The inverse Ackermann function grows so slowly that α(n) ≤ 4 for any n < 10^600.

**In practice: treat it as O(1).**

### Tracing union-find by hand

```
5 elements: {0}, {1}, {2}, {3}, {4}
rank:        0    0    0    0    0

unite(0, 1): parent[1] = 0, rank[0] = 1
  Sets: {0, 1}, {2}, {3}, {4}

unite(2, 3): parent[3] = 2, rank[2] = 1
  Sets: {0, 1}, {2, 3}, {4}

unite(1, 3): find(1) → 0 (compressed), find(3) → 2 (compressed)
  rank[0] = 1, rank[2] = 1, equal → parent[2] = 0, rank[0] = 2
  Sets: {0, 1, 2, 3}, {4}

same(0, 4)? find(0) = 0, find(4) = 4 → NO
same(0, 2)? find(0) = 0, find(2) → 0 (compressed) → YES
```

### Common interview pattern

**"Number of connected components":** Start with n separate sets. For each edge, `unite(u, v)`. If `find(u) == find(v)` already, the edge was redundant (creates a cycle). Count the number of distinct roots at the end.

```cpp
int countComponents(int n, vector<vector<int>>& edges) {
    DSU uf(n);
    int components = n;
    for (auto& e : edges) {
        if (uf.find(e[0]) != uf.find(e[1])) {
            uf.unite(e[0], e[1]);
            components--; // two groups merged into one
        }
    }
    return components;
}
```

## Topological Sort — ordering tasks with dependencies

### Why it exists

You have tasks with prerequisites:
- Task C depends on Task A (A must come first)
- Task D depends on Task B and Task C
- Task A has no dependencies

You need an ordering where **every task comes after all its dependencies**.

**Real-world:** Build systems (`make`, `npm install`), course prerequisites, database migration scripts, pipeline stages in data engineering, package installation order.

### The graph model

Each task is a vertex. Each dependency "B depends on A" is a directed edge A → B. The graph must be a **DAG** (Directed Acyclic Graph) — if there's a cycle, no valid ordering exists.

### Method 1: Kahn's Algorithm (BFS-based)

**Idea:** Repeatedly pick nodes with in-degree 0 (no unprocessed dependencies). Process them, remove their outgoing edges, repeat.

```cpp
vector<int> topologicalSortKahn(int n, const vector<vector<int>>& adj) {
    vector<int> indegree(n, 0);
    for (int u = 0; u < n; u++)
        for (int v : adj[u])
            indegree[v]++;

    queue<int> q;
    for (int i = 0; i < n; i++)
        if (indegree[i] == 0) q.push(i);

    vector<int> result;
    while (!q.empty()) {
        int u = q.front(); q.pop();
        result.push_back(u);

        for (int v : adj[u]) {
            indegree[v]--;
            if (indegree[v] == 0) q.push(v);
        }
    }

    if (result.size() < n) return {}; // cycle detected!
    return result;
}
```

**Cycle detection:** If you process fewer than n nodes, the remaining nodes form a cycle — they all have in-degree > 0 because each depends on another in the cycle.

### Method 2: DFS-based (post-order reversal)

**Idea:** DFS naturally processes dependencies before dependents. Record nodes in **reverse post-order** (add to list after exploring all descendants), then reverse the list.

```cpp
vector<int> topologicalSortDFS(int n, const vector<vector<int>>& adj) {
    vector<int> order;
    vector<int> state(n, 0); // 0 = unvisited, 1 = in progress, 2 = done

    function<void(int)> dfs = [&](int u) {
        state[u] = 1; // mark as in-progress (on recursion stack)
        for (int v : adj[u]) {
            if (state[v] == 1) {
                // v is on our current path → cycle detected
                throw runtime_error("cycle detected");
            }
            if (state[v] == 0) dfs(v);
        }
        state[u] = 2; // mark as done
        order.push_back(u); // post-order: add after all descendants
    };

    for (int i = 0; i < n; i++)
        if (state[i] == 0) dfs(i);

    reverse(order.begin(), order.end()); // reverse post-order = topo order
    return order;
}
```

**Cycle detection:** The `state == 1` check finds a back edge (an edge to a node currently on the recursion stack), which means a cycle.

### Which method to choose?

| Factor | Kahn's (BFS) | DFS |
|--------|-------------|-----|
| Cycle detection | Implicit (count processed nodes) | Explicit (state == 1 back edge) |
| Natural order | Process level by level | Depends on DFS traversal order |
| Interview frequency | More common | Also common |
| Parallel execution | Naturally groups independent tasks (each "level" can run in parallel) | Less obvious |

## Course Schedule (LC 207) — the canonical topological sort problem

Given N courses and prerequisites `[a, b]` meaning "b is required for a", determine if you can finish all courses.

This is exactly topological sort. If the prerequisite graph has a cycle, the answer is no.

```cpp
bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
    vector<vector<int>> adj(numCourses);
    vector<int> indegree(numCourses, 0);

    for (auto& p : prerequisites) {
        adj[p[1]].push_back(p[0]); // p[1] → p[0] (prerequisite to dependent)
        indegree[p[0]]++;
    }

    queue<int> q;
    for (int i = 0; i < numCourses; i++)
        if (indegree[i] == 0) q.push(i);

    int finished = 0;
    while (!q.empty()) {
        int u = q.front(); q.pop();
        finished++;
        for (int v : adj[u]) {
            indegree[v]--;
            if (indegree[v] == 0) q.push(v);
        }
    }

    return finished == numCourses; // all courses processed = no cycle
}
```

**Time:** O(V + E). **Space:** O(V + E).

## Connecting the two topics

Union-Find and Topological Sort solve related but different problems:

| Problem | Union-Find | Topological Sort |
|---------|-----------|-----------------|
| Graph type | Undirected | Directed (DAG) |
| Question | "Are A and B connected?" | "What order should tasks happen?" |
| Dynamic updates | ✅ Efficiently handles new edges | ❌ Re-run from scratch |
| Cycle detection | `find(a) == find(b)` before unite | Kahn's: processed count < n |

**Key distinction:** Union-Find works on **undirected** connectivity. Topological sort works on **directed** dependencies.

## Common Mistakes

| Mistake | What happens | Fix |
|---------|-------------|-----|
| Union-find without path compression | Degrades to O(n) per operation, TLE | Always use `parent[x] = find(parent[x])` |
| Union-find without union by rank | Tree can become deep (though path compression helps) | Use both optimizations together |
| Topo sort not checking for cycles | Returns partial order silently | Verify result.size() == n |
| DFS topo sort forgetting to reverse | Post-order is the opposite of topological order | Reverse after collecting |
| Off-by-one in course schedule | Wrong prerequisite direction | `[a, b]` means b → a (b is prereq for a) |

---

## Recap

- **Union-Find:** Tracks disjoint sets with near-O(1) `find` and `unite`. Two optimizations: path compression (flatten on find) and union by rank (attach shorter to taller). Complexity: O(α(n)).
- **Topological Sort:** Orders tasks so dependencies come first. Two methods: Kahn's algorithm (BFS, remove in-degree-0 nodes) and DFS (reverse post-order). Detects cycles in DAGs.
- **Connected components:** Union-Find counts them efficiently; BFS/DFS does the same but slower per query.
- **Course schedule** (LC 207) is the canonical topological sort interview problem.
