# Complexity Primer (Big-O)

## What is it, in one line?

**Big-O** describes how **time or memory** grows as input size `n` increases—worst-case unless stated otherwise.

---

## Why it exists

At `n = 10^6`, O(n²) is unusable; O(n log n) or O(n) may be fine. Interviews require you to justify scalability.

Hello Algo **Chapter 2** goes deeper: [Computational complexity (EN)](https://www.hello-algo.com/en/chapter_computational_complexity/).

---

## Common classes (slow → fast for large n)

| Big-O | Name | Example |
|-------|------|---------|
| O(2^n) | Exponential | Naive subsets |
| O(n²) | Quadratic | Nested loops over array |
| O(n log n) | Linearithmic | Good sorts, heap ops × n |
| O(n) | Linear | Single scan |
| O(log n) | Logarithmic | Binary search |
| O(1) | Constant | Hash map average lookup |

Drop constants and lower terms: O(3n + 100) → **O(n)**.

---

## Space complexity

Count **extra** structures (not always input):

- Two pointers on array: **O(1)** extra.
- Hash map of n items: **O(n)** extra.
- Recursion depth d: **O(d)** call stack.

---

## Recursion depth

```cpp
int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}
```

Depth n → **O(n)** stack; deep n can overflow—iterate or tail-recursion where compiler allows.

---

## Rules of thumb

- Single loop over n → O(n).
- Loop halving n each time → O(log n).
- Two nested loops over n → O(n²).
- Sort then scan → O(n log n).

---

## Real-world

Database index lookup ~ O(log n) pages; full table scan O(n). Same reason binary search matters.
