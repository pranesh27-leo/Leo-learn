# Dynamic Programming — Framework and 1D DP

Hello Algo **Ch 14**: [Intro to DP](https://www.hello-algo.com/en/chapter_dynamic_programming/intro_to_dynamic_programming/).

## What is it, in one line?

**Dynamic Programming (DP)** solves problems by breaking them into overlapping subproblems, solving each once, and storing the results in a table so you never recompute the same subproblem.

---

## The Pain That Motivates DP

Consider the Fibonacci sequence: `F(n) = F(n-1) + F(n-2)`.

The naive recursive solution:

```cpp
int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);
}
```

This looks clean but is **exponentially slow**. Why? Because `fib(40)` calls `fib(39)` and `fib(38)`, `fib(39)` calls `fib(38)` and `fib(37)`, and so on. The same subproblem (`fib(38)`) is computed twice, `fib(37)` three times, `fib(36)` five times. By `fib(40)`, you're making ~400 million calls.

```
fib(5)
├── fib(4)
│   ├── fib(3)
│   │   ├── fib(2)
│   │   │   ├── fib(1) = 1
│   │   │   └── fib(0) = 0
│   │   └── fib(1) = 1
│   └── fib(2) ← computed AGAIN
│       ├── fib(1) = 1
│       └── fib(0) = 0
└── fib(3) ← computed AGAIN
    ├── fib(2) ← computed YET AGAIN
    └── fib(1) = 1
```

DP eliminates this redundancy by **storing each result once**.

---

## When DP Applies — Two Requirements

A problem can be solved with DP **if and only if** it has both properties:

### 1. Optimal Substructure

The optimal solution to the problem can be constructed from optimal solutions to its subproblems.

**Example:** "Shortest path from A to C via B" = "shortest path A to B" + "shortest path B to C." The global optimum is built from local optima.

**Counter-example:** "Longest simple path" (no repeated vertices) does NOT have optimal substructure. The longest path from A to C via B might use a different path from A to B than the longest standalone path A to B, because the standalone path might use vertices needed later.

### 2. Overlapping Subproblems

The same subproblem is solved multiple times in a naive recursive approach.

**Example:** In Fibonacci, `fib(3)` is computed many times.
**Counter-example:** Merge sort's subproblems are all different — no overlap. That's why merge sort uses divide-and-conquer, not DP.

---

## The DP Framework — Four Steps

Every DP problem is solved by following these steps in order:

### Step 1: Define the State

What does `dp[i]` (or `dp[i][j]`) **mean**? This is the most critical step.

**Good state definition:** "dp[i] = minimum cost to reach position i."
**Bad state definition:** "dp[i] = the answer at index i." (What answer? Be specific.)

**Rule: If you can't explain what dp[i] means in one sentence, you don't have the recurrence.**

### Step 2: Find the Recurrence

How does `dp[i]` relate to earlier values? Think: "To compute dp[i], what choices do I have, and what's the best previous state for each choice?"

**Example (climbing stairs):** To reach step i, you could have come from step i-1 (one step) or step i-2 (two steps). So `dp[i] = dp[i-1] + dp[i-2]`.

### Step 3: Set the Base Cases

What are the values of dp at the start? These are the trivially known values.

**Example:** `dp[0] = 1` (one way to stand at the bottom: do nothing), `dp[1] = 1` (one way to reach step 1: take one step).

### Step 4: Choose the Computation Order

Fill the table in an order where every cell you need has already been computed. For 1D DP, this is usually left to right (i = 1, 2, 3, ...).

## Example 1: Climbing Stairs (LC 70)

**Problem:** You can climb 1 or 2 steps at a time. How many distinct ways to climb n steps?

### Step-by-step DP framework:

1. **State:** `dp[i]` = number of distinct ways to reach step i
2. **Recurrence:** `dp[i] = dp[i-1] + dp[i-2]` (you arrive from i-1 with a 1-step, or from i-2 with a 2-step)
3. **Base cases:** `dp[0] = 1` (standing at ground), `dp[1] = 1` (one 1-step)
4. **Order:** Left to right, i = 2 to n

```cpp
int climbStairs(int n) {
    if (n <= 1) return 1;
    vector<int> dp(n + 1);
    dp[0] = 1; dp[1] = 1;
    for (int i = 2; i <= n; i++)
        dp[i] = dp[i-1] + dp[i-2];
    return dp[n];
}
```

### Space Optimization: O(1)

Notice that `dp[i]` depends only on the **previous two values**. You don't need the whole array:

```cpp
int climbStairs(int n) {
    if (n <= 2) return n;
    int a = 1, b = 2; // dp[1] and dp[2]
    for (int i = 3; i <= n; i++) {
        int c = a + b;
        a = b;
        b = c;
    }
    return b;
}
```

**Time:** O(n). **Space:** O(1).

### Three versions, same answer

| Version | Space | Trade-off |
|---------|-------|-----------|
| Full array `dp[0..n]` | O(n) | Easy to debug, can inspect intermediate values |
| Two variables (a, b) | O(1) | Fast, minimal memory |
| Memoized recursion | O(n) stack + O(n) table | Natural top-down thinking, same complexity |

## Example 2: House Robber (LC 198)

**Problem:** Rob houses in a street. You can't rob two adjacent houses (they trigger alarms). Maximize total loot.

### Step-by-step:

1. **State:** `dp[i]` = maximum loot from houses 0 through i
2. **Recurrence:** For house i, you either rob it (`nums[i] + dp[i-2]`) or skip it (`dp[i-1]`):
   ```
   dp[i] = max(dp[i-1], nums[i] + dp[i-2])
   ```
3. **Base cases:** `dp[0] = nums[0]`, `dp[1] = max(nums[0], nums[1])`
4. **Order:** Left to right

```cpp
int rob(vector<int>& nums) {
    if (nums.empty()) return 0;
    if (nums.size() == 1) return nums[0];

    int prev2 = nums[0];
    int prev1 = max(nums[0], nums[1]);

    for (int i = 2; i < nums.size(); i++) {
        int current = max(prev1, nums[i] + prev2);
        prev2 = prev1;
        prev1 = current;
    }
    return prev1;
}
```

**Time:** O(n). **Space:** O(1).

## Example 3: Minimum Cost Climbing Stairs (LC 746)

**Problem:** Each step has a cost. You can climb 1 or 2 steps. Find the minimum cost to reach the top (beyond the last step).

### Step-by-step:

1. **State:** `dp[i]` = minimum cost to reach step i
2. **Recurrence:** `dp[i] = cost[i] + min(dp[i-1], dp[i-2])` — to reach step i, you pay cost[i] plus the minimum of arriving from i-1 or i-2
3. **Base cases:** `dp[0] = cost[0]`, `dp[1] = cost[1]`
4. **Answer:** `min(dp[n-1], dp[n-2])` — you can reach the top from the last step or the second-to-last step

```cpp
int minCostClimbingStairs(vector<int>& cost) {
    int n = cost.size();
    int a = cost[0], b = cost[1];
    for (int i = 2; i < n; i++) {
        int c = cost[i] + min(a, b);
        a = b;
        b = c;
    }
    return min(a, b); // reach top from last or second-to-last step
}
```

## Top-Down (Memoization) vs Bottom-Up (Tabulation)

### Top-Down — start from the answer and work down

```cpp
memo = array of -1
int dp(int i) {
    if (i <= 1) return 1;                    // base case
    if (memo[i] != -1) return memo[i];       // return cached result
    return memo[i] = dp(i-1) + dp(i-2);      // compute and cache
}
```

**Pros:** Natural to write (it's just the recursive solution + cache). Only computes subproblems that are actually needed.
**Cons:** Recursion overhead (stack space, function calls). Can stack overflow on very deep recursions.

### Bottom-Up — start from base cases and build up

```cpp
dp[0] = 1; dp[1] = 1;
for (int i = 2; i <= n; i++)
    dp[i] = dp[i-1] + dp[i-2];
```

**Pros:** No recursion overhead. Easy to optimize space (keep only needed previous values).
**Cons:** May compute subproblems that aren't needed (usually not a practical concern for 1D DP).

### Recommendation

Start with top-down when learning — it mirrors your natural recursive thinking. Convert to bottom-up for space optimization and production code.

## The 1D DP Checklist

Before writing code, fill in these blanks:

1. **dp[i] means:** ___________________________________
2. **Recurrence:** dp[i] = ___________________________
3. **Base case(s):** dp[0] = ___, dp[1] = ___
4. **Computation order:** left→right (or right→left if needed)
5. **Answer is at:** dp[n] (or dp[n-1], or some specific cell)
6. **Can I optimize space?** Does dp[i] depend on only the last k values? If k is small (1, 2, or 3), use variables instead of an array.

---

## Common Mistakes

| Mistake | What happens | Fix |
|---------|-------------|-----|
| Wrong state definition | Recurrence doesn't work or gives wrong answer | Be explicit: "dp[i] = [what?]" in plain English |
| Off-by-one in base cases | dp[0] should be 1 but you set it to 0 | Trace through i=0, i=1, i=2 by hand |
| Using `min` when you need `max` | Minimizing instead of maximizing (or vice versa) | Read the problem statement: "minimum" or "maximum"? |
| Not handling empty input | Segfault on `dp[0]` when array is empty | Check `if (nums.empty()) return 0;` at the start |
| Forgetting that dp depends on previous values | Initializing dp with zeros and not filling in order | Always fill base cases before the main loop |

## Connecting to Real-World Patterns

| 1D DP pattern | Real-world application |
|--------------|----------------------|
| "Max with skip" (house robber) | Scheduling tasks with cooldown, placing cell towers on a road |
| "Min cost path" (min cost stairs) | Finding cheapest route with step-by-step decisions |
| "Count ways" (climbing stairs) | Combinatorial counting, password strength estimation |
| "Partition/equal sum" (subset sum) | Budget allocation, load balancing |

---

## Recap

- **DP = optimal substructure + overlapping subproblems.** When both hold, store subproblem results in a table.
- **Four steps:** Define state → find recurrence → set base cases → choose computation order.
- **1D DP:** `dp[i]` depends on a small number of previous values (usually dp[i-1] and dp[i-2]).
- **Space optimization:** If dp[i] needs only the last k values, use k variables instead of an array.
- **Top-down** (memoization) is natural to write; **bottom-up** (tabulation) is faster and uses less memory.
- The hardest part is always Step 1: defining what `dp[i]` means. Everything else follows.
