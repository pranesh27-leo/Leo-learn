# Monotonic Stack and Advanced Array

## What is it, in one line?

A **monotonic stack** maintains elements in sorted order (increasing or decreasing) as you scan through an array. Each element is pushed once and popped at most once, giving you O(n) total time to answer "next greater element" questions.

---

## Why it exists

When you need to find, for each element, the **first element to its left or right that satisfies some ordering condition** (bigger, smaller, nearest, farthest), a naive approach is O(n²) — for each element, scan left/right until you find the answer.

The monotonic stack reduces this to O(n) by maintaining a stack where elements are always in monotonic order. When a new element breaks the order, you pop and process.

**Real-world:** Stock analytics ("how many days until the price goes above today?"), histogram area calculations, nearest landmark queries, building skyline rendering.

---

## The Four Variants

| Variant | Stack order | Answer for each element |
|---------|------------|------------------------|
| **Next Greater Element** | Decreasing stack | First element to the **right** that is **larger** |
| **Next Smaller Element** | Increasing stack | First element to the **right** that is **smaller** |
| **Previous Greater Element** | Decreasing stack | First element to the **left** that is **larger** |
| **Previous Smaller Element** | Increasing stack | First element to the **left** that is **smaller** |

All four use the same mechanism — scan direction and comparison operator change, but the stack logic is identical.

## Variant 1: Next Greater Element (LC 739 — Daily Temperatures)

**Problem:** Given `temperatures = [73,74,75,71,69,72,76,73]`, for each day, how many days until a warmer temperature?

```
Index:    0   1   2   3   4   5   6   7
Temp:     73  74  75  71  69  72  76  73
Answer:   1   1   4   2   1   1   0   0
```

**Idea:** Scan left to right. Maintain a stack of indices where temperatures are **decreasing**. When you see a temperature warmer than the stack top, pop it — you've found its next greater element.

```cpp
vector<int> dailyTemperatures(vector<int>& t) {
    int n = t.size();
    vector<int> answer(n, 0);       // default 0 = no warmer day ahead
    stack<int> st;                  // indices of decreasing temperatures

    for (int i = 0; i < n; i++) {
        // While current temp is warmer than stack top's temp:
        while (!st.empty() && t[i] > t[st.top()]) {
            int prevIdx = st.top();
            st.pop();
            answer[prevIdx] = i - prevIdx; // days until warmer
        }
        st.push(i); // push current index (stack stays decreasing)
    }
    return answer;
}
```

### Tracing by hand

```
i=0, t[0]=73:  stack: [0(73)]
i=1, t[1]=74:  74>73 → pop 0, answer[0]=1-0=1. stack: [1(74)]
i=2, t[2]=75:  75>74 → pop 1, answer[1]=2-1=1. stack: [2(75)]
i=3, t[3]=71:  71<75 → push. stack: [2(75), 3(71)]
i=4, t[4]=69:  69<71 → push. stack: [2(75), 3(71), 4(69)]
i=5, t[5]=72:  72>69 → pop 4, answer[4]=5-4=1
                 72>71 → pop 3, answer[3]=5-3=2
                 72<75 → stop. stack: [2(75), 5(72)]
i=6, t[6]=76:  76>72 → pop 5, answer[5]=6-5=1
                 76>75 → pop 2, answer[2]=6-2=4. stack: [6(76)]
i=7, t[7]=73:  73<76 → push. stack: [6(76), 7(73)]

End: remaining stack elements get answer=0 (default).
Result: [1, 1, 4, 2, 1, 1, 0, 0] ✓
```

### Why O(n)? Each element is pushed exactly once and popped at most once. Total operations = 2n = O(n).

## Variant 2: Largest Rectangle in Histogram (LC 84)

**Problem:** Given bar heights `[2,1,5,6,2,3]`, find the largest rectangular area.

```
   █
 █ █ █ █
 █ █ █ █ █ █
 2 1 5 6 2 3
```

**Insight:** For each bar, find how far it can extend to the left and right while all bars are ≥ its height. The width × height gives the area.

**How:** Use a monotonic **increasing** stack. When you encounter a bar shorter than the stack top, pop it — you've found the right boundary for that bar. The left boundary is the new stack top (or -1 if empty).

```cpp
int largestRectangleArea(vector<int>& heights) {
    heights.push_back(0); // sentinel: force all elements to pop
    stack<int> st; // indices, heights are increasing
    int maxArea = 0;

    for (int i = 0; i < heights.size(); i++) {
        while (!st.empty() && heights[i] < heights[st.top()]) {
            int h = heights[st.top()];
            st.pop();
            int w = st.empty() ? i : i - st.top() - 1;
            maxArea = max(maxArea, h * w);
        }
        st.push(i);
    }
    return maxArea;
}
```

### Why the sentinel works

Adding 0 at the end ensures every element eventually gets popped. When you pop an element with height h:
- **Right boundary:** current index `i` (the first element to the right that's shorter)
- **Left boundary:** `st.top()` after popping (the first element to the left that's shorter, or -1 if stack empty)
- **Width:** right - left - 1

## Variant 3: Next Permutation (LC 31)

**Problem:** Rearrange numbers into the next lexicographically greater permutation. `[1,2,3] → [1,3,2]`.

**Algorithm (three steps):**
1. **Find the pivot:** Scan right to left, find the first element that's smaller than its right neighbor.
2. **Find the successor:** Scan right to left, find the first element larger than the pivot.
3. **Reverse:** Reverse everything after the pivot position.

```cpp
void nextPermutation(vector<int>& nums) {
    int n = nums.size();

    // Step 1: Find pivot (rightmost element smaller than its right neighbor)
    int i = n - 2;
    while (i >= 0 && nums[i] >= nums[i + 1]) i--;

    if (i >= 0) {
        // Step 2: Find successor (rightmost element larger than nums[i])
        int j = n - 1;
        while (nums[j] <= nums[i]) j--;
        swap(nums[i], nums[j]);
    }

    // Step 3: Reverse the suffix after position i
    reverse(nums.begin() + i + 1, nums.end());
}
```

This isn't a classic monotonic stack problem, but it uses the same "scan from the right, find the first breaking point" insight.

---

## Common Mistakes

| Mistake | What happens | Fix |
|---------|-------------|-----|
| Stack order wrong (increasing vs decreasing) | Gets "next smaller" instead of "next greater" | Ask: "I want the first element that is X" → stack stores elements in the opposite order of X |
| Not using a sentinel | Elements remain on stack at the end, missed processing | Push 0 (for min problems) or ∞ (for max problems) at the end |
| Comparing values instead of indices | Lose the position information | Store indices in the stack, compare `arr[st.top()]` with `arr[i]` |
| Forgetting that each element is pushed/popped once | Think it's O(n²) | Key insight: total pushes = n, total pops ≤ n, so O(n) |

---

## When to Reach for Monotonic Stack

| Signal in the problem | Pattern |
|----------------------|---------|
| "For each element, find the nearest element to the left/right that is bigger/smaller" | **Monotonic stack** |
| "Next greater element" | Decreasing stack, scan left to right |
| "Previous greater element" | Decreasing stack, or reverse the array |
| "Largest rectangle in histogram" | Increasing stack with sentinel |
| "Stock span" (consecutive prior days ≤ today) | Decreasing stack |
| "Number of visible people in a queue" | Decreasing stack |

---

## Recap

- **Monotonic stack:** maintain elements in sorted order. When a new element breaks the order, pop and process.
- **Next greater/smaller:** O(n) by pushing each element once and popping at most once.
- **Largest rectangle in histogram:** increasing stack, sentinel at end, width = right boundary - left boundary - 1.
- **Key invariant:** the stack is always monotonic. Every pop represents finding the answer for a previously unseen element.
- The pattern is the trickiest O(n) algorithm — build both the naive O(n²) and stack O(n) versions to internalize the speedup.
