# Divide and Conquer

Hello Algo **Ch 12**: [Divide and conquer](https://www.hello-algo.com/en/chapter_divide_and_conquer/divide_and_conquer/).

## What is it, in one line?

**Divide and conquer** splits a problem into smaller subproblems of the same type, solves each recursively, then **combines** the results. The combine step is what distinguishes it from simple recursion.

---

## Why it exists

When the problem size is large, dividing it gives you **parallelism** (subproblems are independent) and often **better asymptotic complexity** (O(n log n) instead of O(n²)). Nearly every efficient algorithm you've seen so far uses D&C:

- **Merge sort** (Week 4.2) — split array in half, sort each, merge
- **Binary search** (Week 3.4) — split search space in half each step
- **Quick sort** (Week 4.2) — partition around pivot, recurse on each side
- **Closest pair of points** (advanced) — split by vertical line, recurse, combine with a strip

The pattern is always the same three steps, regardless of the problem.

---

## The D&C Template

```
solve(problem):
    1. BASE CASE: if problem is small enough, solve directly
    2. DIVIDE:    split into 2+ subproblems of the same type
    3. CONQUER:   recursively solve each subproblem
    4. COMBINE:   merge subproblem results into the final answer
```

### Key properties

| Property | Why it matters |
|----------|---------------|
| **Subproblems are independent** | They can be solved in parallel or any order |
| **Subproblems are the same type** | You reuse the same `solve()` function |
| **Subproblems are strictly smaller** | Guarantees termination (base case is reached) |
| **Combine step is non-trivial** | If combine is O(1), it's just recursion, not D&C |

## Example 1: Merge Sort — D&C on sorting

Let's trace the D&C structure explicitly:

```
solve(array [38, 27, 43, 3, 9, 82, 10]):

BASE CASE?  No (length > 1)

DIVIDE:    [38, 27, 43, 3]  and  [9, 82, 10]

CONQUER:   Recursively sort each half
           → [3, 27, 38, 43]    and    [9, 10, 82]

COMBINE:   Merge the two sorted halves
           → [3, 9, 10, 27, 38, 43, 82]
```

**The combine step** (merge) is O(n) — it walks through both sorted halves simultaneously.

### Complexity analysis using the Master Theorem

For divide and conquer: T(n) = a·T(n/b) + f(n)

| Term | Meaning | Merge sort values |
|------|---------|-------------------|
| a | Number of subproblems | 2 |
| b | Size reduction factor | 2 (each half) |
| f(n) | Cost of divide + combine | O(n) (the merge) |

T(n) = 2T(n/2) + O(n) → **O(n log n)** by the Master Theorem (case 2).

## Example 2: Maximum Subarray (LC 53) — D&C version

The classic Kadane's algorithm solves this with DP, but the D&C version teaches the combine step.

**Problem:** Find the contiguous subarray with the largest sum.

**D&C approach:**
- Split array in half
- Maximum subarray is in one of three places:
  1. Entirely in the left half (recursive call)
  2. Entirely in the right half (recursive call)
  3. **Crosses the midpoint** (combine step — this is the key insight)

```cpp
long long maxSubArray(vector<int>& nums) {
    return divide(nums, 0, nums.size() - 1);
}

long long divide(const vector<int>& nums, int left, int right) {
    // BASE CASE: single element
    if (left == right) return nums[left];

    int mid = left + (right - left) / 2;

    // CONQUER: solve left and right halves
    long long leftMax  = divide(nums, left, mid);
    long long rightMax = divide(nums, mid + 1, right);

    // COMBINE: find max subarray crossing the midpoint
    long long leftCross = 0, crossLeftSum = 0;
    for (int i = mid; i >= left; i--) {
        crossLeftSum += nums[i];
        leftCross = max(leftCross, crossLeftSum);
    }

    long long rightCross = 0, crossRightSum = 0;
    for (int i = mid + 1; i <= right; i++) {
        crossRightSum += nums[i];
        rightCross = max(rightCross, crossRightSum);
    }

    long long crossMax = leftCross + rightCross;

    return max({leftMax, rightMax, crossMax});
}
```

**Complexity:** T(n) = 2T(n/2) + O(n) → O(n log n). (Kadane's DP version is O(n) — faster, but D&C teaches the pattern.)

**The combine insight:** The crossing subarray's maximum is found by scanning left from mid (taking the best suffix of the left half) and right from mid+1 (taking the best prefix of the right half). You can't find this from the recursive results alone — you must do additional work.

## Example 3: Binary Search — D&C on a sorted range

Binary search is the simplest D&C: divide = split range in half, conquer = recurse on one half, combine = the result *is* the subproblem result (no merge needed).

```cpp
int binarySearch(const vector<int>& nums, int target) {
    int left = 0, right = nums.size() - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == target) return mid;
        if (nums[mid] < target) left = mid + 1;   // conquer: right half
        else right = mid - 1;                       // conquer: left half
    }
    return -1;
}
```

**Complexity:** T(n) = T(n/2) + O(1) → **O(log n)**. The combine step is O(1) — you just return the subproblem's answer.

## When to reach for D&C

| Signal in the problem | D&C application |
|-----------------------|----------------|
| "Find the maximum/minimum subarray, submatrix" | Split by midpoint, combine crossing case |
| "Sort or search in large data" | Merge sort, binary search |
| "Problem can be split into independent halves" | Any D&C — look for the combine step |
| "Closest pair", "convex hull" (advanced) | Geometric D&C |
| "Inversion count" (how far from sorted) | Modified merge sort — count during the merge |

---

## D&C vs Other Patterns

| Pattern | Key difference from D&C |
|---------|------------------------|
| **Dynamic Programming** | Subproblems **overlap** — same subproblem solved many times. D&C subproblems are **independent**. |
| **Greedy** | Makes one choice and never looks back. D&C explores all branches. |
| **Backtracking** | Explores all possibilities in a search tree. D&C splits and merges, doesn't backtrack. |
| **Simple recursion** | No combine step — the answer comes directly from one subproblem (like binary search). |

---

## Common Mistakes

| Mistake | What happens | Fix |
|---------|-------------|-----|
| Forgetting the crossing case (max subarray) | Wrong answer — only considers left/right, not the bridge | Always think: "can the answer cross the divide point?" |
| Off-by-one in midpoint | Infinite recursion or missed element | `mid = left + (right - left) / 2`, recurse on `[left, mid]` and `[mid+1, right]` |
| Combine step is O(n²) | Overall complexity worse than brute force | The combine step must be O(n) or less for D&C to help |
| No base case | Stack overflow | Always check `left >= right` or `n <= 1` |

## Recap

- **D&C = Divide → Conquer → Combine.** All three steps must be present (combine can be O(1)).
- **Master Theorem:** T(n) = aT(n/b) + f(n) — gives complexity from the recurrence.
- **Merge sort** (O(n log n)) and **binary search** (O(log n)) are the two canonical examples.
- **Maximum subarray** shows the critical "combine" step — the crossing case that neither subproblem alone can solve.
- D&C subproblems are **independent** (unlike DP) and explore **all branches** (unlike greedy).
