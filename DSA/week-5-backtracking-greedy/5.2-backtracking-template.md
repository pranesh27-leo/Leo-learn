# Backtracking Template

Hello Algo **Ch 13**: [Backtracking](https://www.hello-algo.com/en/chapter_backtracking/backtracking_algorithm/).

## What is it, in one line?

**Backtracking** is systematic trial and error: try a choice, recurse deeper, and if it leads to a dead end, **undo the choice** and try the next one. It explores the entire decision tree, but prunes branches early when possible.

---

## Why it exists

Some problems have no known efficient algorithm. They require trying all (or most) possibilities:
- **Constraint satisfaction** — Sudoku, N-Queens, exam timetabling
- **Combinatorial generation** — all subsets, all permutations, all combinations of size k
- **Pathfinding with constraints** — maze solving with obstacles, word search in a grid
- **Optimization with discrete choices** — knapsack (before you learn DP), task scheduling

When the problem asks "find ALL solutions" or "find ANY valid assignment under constraints," backtracking is usually the right tool.

---

## The Core Idea — Decision Tree

Every backtracking problem is a tree of decisions. Each level of the tree is a **choice point**, each branch is a **possible value**, and each leaf is a **complete solution** (or a dead end).

```
Sudoku example — filling cell by cell:

Root (empty board)
├── Cell (0,0) = 1
│   ├── Cell (0,1) = 2
│   │   ├── Cell (0,2) = 3  ... (valid? continue)
│   │   └── Cell (0,1) = 3  ... (valid? continue)
│   └── Cell (0,1) = 3
├── Cell (0,0) = 2
│   └── ...
```

Backtracking walks this tree depth-first. When it hits a dead end (no valid choice for the current cell), it **backtracks** to the previous decision point and tries the next option.

## The Template

```cpp
void backtrack(state, choices) {
    // 1. BASE CASE: are we done?
    if (complete(state)) {
        recordSolution(state);
        return;
    }

    // 2. TRY each valid choice
    for (choice : choices) {
        if (!isValid(choice, state)) continue; // prune: skip invalid choices

        // 3. APPLY the choice
        apply(choice, state);

        // 4. RECURSE deeper
        backtrack(state, nextChoices);

        // 5. UNDO the choice (backtrack!)
        undo(choice, state);
    }
}
```

### The five steps, explained

| Step | Purpose | Common mistake |
|------|---------|----------------|
| **Base case** | Stop recursion when solution is complete | Forgetting to check → infinite recursion or incomplete solutions recorded |
| **Validity check** | Prune branches early — don't explore invalid states | Skipping this → exponential blowup |
| **Apply** | Make the choice permanent for the deeper recursion | Applying after recursion (wrong order) |
| **Recurse** | Go deeper with the choice in place | Not passing updated state |
| **Undo** | Restore state for the next sibling branch | Forgetting → all future branches see this choice |

**The undo step is the most critical.** Without it, every branch carries all previous choices, and you don't get a tree — you get a line.

## Example 1: Subsets (LC 78) — include or exclude

**Problem:** Given `[1, 2, 3]`, return all subsets: `[], [1], [2], [3], [1,2], [1,3], [2,3], [1,2,3]`.

**Decision at each element:** Include it or don't. That's a binary choice → 2ⁿ leaves.

```cpp
void backtrack(const vector<int>& nums, int start, vector<int>& current, vector<vector<int>>& result) {
    // Record the current subset (every node in the tree is a valid subset)
    result.push_back(current);

    // Try including each remaining element
    for (int i = start; i < nums.size(); i++) {
        current.push_back(nums[i]);       // APPLY
        backtrack(nums, i + 1, current, result); // RECURSE
        current.pop_back();               // UNDO
    }
}
```

**Complexity:** O(2ⁿ) subsets, each taking O(n) to copy. Total: O(n · 2ⁿ).

**Key insight:** The base case isn't explicit — every node in the decision tree represents a valid subset, so we record at the top of each call.

## Example 2: Permutations (LC 46) — each element used exactly once

**Problem:** Given `[1, 2, 3]`, return all permutations: `[1,2,3], [1,3,2], [2,1,3], ...`.

**Difference from subsets:** Each element must appear exactly once. We need a `used` array.

```cpp
void backtrack(const vector<int>& nums, vector<int>& current, vector<bool>& used, vector<vector<int>>& result) {
    // BASE CASE: all elements used
    if (current.size() == nums.size()) {
        result.push_back(current);
        return;
    }

    for (int i = 0; i < nums.size(); i++) {
        if (used[i]) continue; // skip already-used elements

        used[i] = true;                    // APPLY
        current.push_back(nums[i]);
        backtrack(nums, current, used, result); // RECURSE
        current.pop_back();               // UNDO
        used[i] = false;                  // UNDO
    }
}
```

**Complexity:** O(n!) permutations, each O(n) to build. Total: O(n · n!).

## Example 3: N-Queens (Hello Algo 13.4) — constraint satisfaction

**Problem:** Place N queens on an N×N board so no two queens attack each other (same row, column, or diagonal).

**Strategy:** Place one queen per row (this eliminates the row constraint by construction). For each row, try every column. Check column and diagonal constraints.

```cpp
void solveNQueens(int n, int row, vector<string>& board, vector<vector<string>>& result) {
    if (row == n) { // BASE CASE: all queens placed
        result.push_back(board);
        return;
    }

    for (int col = 0; col < n; col++) {
        if (!isSafe(board, row, col)) continue; // VALIDITY CHECK

        board[row][col] = 'Q';        // APPLY
        solveNQueens(n, row + 1, board, result); // RECURSE
        board[row][col] = '.';        // UNDO
    }
}

bool isSafe(const vector<string>& board, int row, int col) {
    int n = board.size();
    for (int i = 0; i < row; i++) {
        // Check column
        if (board[i][col] == 'Q') return false;
        // Check upper-left diagonal
        if (col - (row - i) >= 0 && board[i][col - (row - i)] == 'Q') return false;
        // Check upper-right diagonal
        if (col + (row - i) < n && board[i][col + (row - i)] == 'Q') return false;
    }
    return true;
}
```

**Pruning is everything:** Without the `isSafe` check, you'd try all nⁿ placements. With it, you prune branches the moment a queen attacks another — for n=8, this reduces from 8⁸ = 16 million to just a few thousand nodes explored.

## Pruning Strategies — Making Backtracking Fast

Raw backtracking is exponential. Pruning is what makes it usable:

| Technique | Idea | Effect |
|-----------|------|--------|
| **Early validity check** | Don't recurse if the choice is already invalid | Cuts entire subtrees |
| **Sort choices by most constrained** | Try the cell/variable with fewest valid options first | Fails fast on hard choices |
| **Symmetry breaking** | Don't try equivalent configurations | Cuts the search space by a constant factor |
| **Forward checking** | After a choice, check if any future variable has zero options | Detects dead ends before recursing |

**The most-constrained-variable heuristic** (also called MRV — Minimum Remaining Values) is the single most effective pruning strategy. In Sudoku, fill the cell with the fewest valid digits first. This exposes dead ends earlier, saving you from exploring deep branches that will fail anyway.

---

## When Backtracking is the Right Choice

| Problem says… | Reach for… |
|---------------|-----------|
| "Find all subsets/permutations/combinations" | Backtracking (straightforward tree) |
| "Place items with constraints" (Sudoku, N-Queens) | Backtracking + pruning |
| "Find all paths from A to B" | DFS/backtracking |
| "Is there ANY valid assignment?" | Backtracking with early return |
| "Optimize a discrete choice" | Try greedy first; if greedy fails, backtracking or DP |

---

## Backtracking vs Related Patterns

| Pattern | Key difference |
|---------|---------------|
| **DFS on a graph** | DFS visits each node once. Backtracking revisits nodes with different choices. |
| **D&C** | D&C splits into independent subproblems. Backtracking's branches interact through constraints. |
| **Greedy** | Greedy picks one choice and commits. Backtracking tries all choices. |
| **DP** | DP memoizes overlapping subproblems. Backtracking's subproblems are usually distinct (different partial assignments). |

---

## Common Mistakes

| Mistake | What happens | Fix |
|---------|-------------|-----|
| Forgetting to undo | All branches see all choices; wrong results | Always have a symmetric apply/undo pair |
| Not checking validity before recursing | Exponential blowup from exploring dead branches | `if (!isValid) continue;` before apply |
| Off-by-one in base case | Missing solutions or recording incomplete ones | Test with n=1 and n=2 by hand |
| Passing state by value when it should be reference | Each recursive call gets a copy → undo doesn't work for siblings | Pass by reference, undo after recursion |

---

## Recap

- **Backtracking = try → recurse → undo.** Explore the decision tree depth-first.
- **Template:** Base case → for each choice → if valid → apply → recurse → undo.
- **Pruning** (validity checks, most-constrained-first) is what makes exponential algorithms practical.
- **Subsets** (include/exclude), **permutations** (used array), and **N-Queens** (constraint checking) are the three canonical patterns.
- The **undo step** is non-negotiable — without it, you don't have a tree, you have a line.
