# Greedy Algorithms — Proofs and Intuition

Hello Algo **Ch 15**: [Greedy](https://www.hello-algo.com/en/chapter_greedy/greedy_algorithm/).

## What is it, in one line?

**Greedy** means: at each step, make the locally optimal choice and **never look back**. If the greedy choice is provably optimal, you get an O(n) or O(n log n) algorithm instead of exponential backtracking or DP.

But greedy is the **most dangerous** pattern — it's easy to get wrong, easy to convince yourself it's right, and the failure cases are subtle.

---

## Why it exists

Some problems have the structure that a myopic, one-step decision leads to the global optimum:
- **Interval scheduling** — "which meeting should I accept next?"
- **Activity selection** — "which task to schedule?"
- **Change making** — "which coin to use?" (works for US currency, fails for arbitrary coin systems)
- **Huffman coding** — optimal prefix-free encoding
- **Kruskal's / Prim's MST** — optimal spanning tree

When greedy works, it gives the simplest and fastest solution. When it doesn't, you need DP or backtracking.

---

## The Greedy Template

```
sort or order the input (if the greedy strategy depends on ordering)
result = empty
for each item (in the chosen order):
    if choosing this item is compatible with previous choices:
        choose it
return result
```

### The two critical questions

Every greedy solution must answer:
1. **What is the greedy choice?** (sort by end time? pick the largest? pick the smallest?)
2. **Why is the greedy choice optimal?** (this is the proof — without it, you're guessing)

---

## How to Prove Greedy is Optimal — the Exchange Argument

The standard proof technique for greedy algorithms:

### Step 1: Define the greedy solution G and an optimal solution O

### Step 2: Find the first step where G and O differ

### Step 3: Show that you can **modify O** to match G's choice at that step **without making O worse**

### Step 4: Repeat until O = G, proving G is also optimal

**In practice:** You usually prove that choosing the "earliest-ending" (or "smallest," or "largest") item is always at least as good as any other choice. The exchange argument shows: "if an optimal solution doesn't pick this item, we can swap in our greedy choice and the solution is still optimal."

## Example 1: Jump Game (LC 55)

**Problem:** Given `[2,3,1,1,4]`, can you reach the last index? From index i, you can jump up to `nums[i]` steps.

**Greedy insight:** Track the farthest reachable index. Scan left to right; at each position, update the farthest you can reach. If you ever can't reach the current position, you're stuck.

```cpp
bool canJump(vector<int>& nums) {
    int farthest = 0;
    for (int i = 0; i < nums.size(); i++) {
        if (i > farthest) return false; // can't even reach position i
        farthest = max(farthest, i + nums[i]);
        if (farthest >= nums.size() - 1) return true; // early exit
    }
    return true;
}
```

**Complexity:** O(n) time, O(1) space. One pass.

**Why greedy works:** At each position i, you want to maximize your reach. The farthest you can reach from any position j ≤ i is `max(farthest, i + nums[i])`. If `farthest ≥ n-1`, you can reach the end. You never need to look back because `farthest` already captures the best reach from all previous positions.

**Proof sketch:** Suppose the optimal path reaches position k. The greedy algorithm reaches at least as far (it takes the maximum over all reachable positions). Therefore if any path reaches the end, the greedy farthest-reaches also reaches the end.

## Example 2: Greedy Coin Change — and When It Fails

**Problem:** Given coins `[1, 5, 10, 25]` and amount 30, make change with the fewest coins.

**Greedy strategy:** Always take the largest coin ≤ remaining amount.
- 30 → take 25, remaining 5 → take 5 → total: 2 coins ✓

**When greedy fails:** Coins `{1, 3, 4}`, amount 6.
- Greedy: 4 + 1 + 1 = **3 coins**
- Optimal: 3 + 3 = **2 coins**

**This is the most important exercise in the entire week.** Greedy fails visibly, and now you know why you must prove it before trusting it.

**When greedy works for coin change:** When the coin system is **canonical** — each coin is a multiple of the previous (like US: 1, 5, 10, 25) or satisfies a specific mathematical property (each coin ≥ 2 × the previous coin that isn't a multiple).

## Example 3: Task Scheduler (LC 621) — greedy on frequencies

**Problem:** Given tasks `['A','A','A','B','B','C']` and cooldown n=2, find minimum intervals to complete all tasks.

**Greedy strategy:** Always execute the most frequent task first. Use a max-heap on frequencies.

```cpp
int leastInterval(vector<char>& tasks, int n) {
    vector<int> freq(26, 0);
    for (char t : tasks) freq[t - 'A']++;

    priority_queue<int> maxHeap;
    for (int f : freq) if (f > 0) maxHeap.push(f);

    int time = 0;
    queue<pair<int, int>> cooldown; // {frequency, availableTime}

    while (!maxHeap.empty() || !cooldown.empty()) {
        time++;
        if (maxHeap.empty()) {
            time = max(time, cooldown.back().second); // skip idle time
        } else {
            int freq = maxHeap.top(); maxHeap.pop();
            if (freq > 1) cooldown.push({freq - 1, time + n});
        }
        if (!cooldown.empty() && cooldown.front().second == time) {
            maxHeap.push(cooldown.front().first);
            cooldown.pop();
        }
    }
    return time;
}
```

**Alternative formula:** `max(n_tasks, (maxFreq - 1) * (n + 1) + countOfMaxFreq)`. The greedy simulation arrives at the same answer.

## Example 4: Fractional Knapsack — greedy works here (but not 0/1 knapsack)

**Problem:** Maximize value in a knapsack of capacity W. Items have weight and value. **You can take fractions of items.**

**Greedy strategy:** Sort by value/weight ratio (highest first). Take as much as you can of each item.

```cpp
double fractionalKnapsack(int W, vector<pair<int,int>>& items) { // {weight, value}
    // Sort by value/weight ratio descending
    sort(items.begin(), items.end(), [](const auto& a, const auto& b) {
        return (double)a.second / a.first > (double)b.second / b.first;
    });

    double value = 0;
    for (auto& [weight, val] : items) {
        if (W >= weight) {
            value += val;      // take the whole item
            W -= weight;
        } else {
            value += (double)val * W / weight; // take fraction
            W = 0;
            break;
        }
    }
    return value;
}
```

**Why greedy works for fractional but not 0/1 knapsack:** When you can take fractions, the highest ratio item is always the best marginal contribution. When you can't, taking a high-ratio item might fill the knapsack with a low-total-value item, when two medium-ratio items would fit and give more total value.

**Exchange argument for fractional knapsack:** Suppose optimal solution O doesn't take the highest-ratio item fully. Replace some lower-ratio content with the higher-ratio item. The total value increases or stays the same. Repeat until the highest-ratio item is maximized. QED.

## When to Reach for Greedy (and When NOT To)

| Problem asks for… | Greedy? | Why? |
|-------------------|---------|------|
| "Minimum/maximum" with **independent choices** | ✅ Likely | Each choice doesn't affect future feasibility |
| "Minimum intervals to remove" | ✅ Sort by end time | Classic greedy |
| "Minimum coins" (arbitrary coin system) | ❌ | Greedy fails for {1,3,4} |
| "Minimum coins" (canonical system) | ✅ | US/EUR/INR coin systems work |
| "Shortest path" (weighted) | ❌ | Need Dijkstra (greedy on distance, but with relaxation) |
| "Maximum profit with at most K transactions" | ❌ Need DP | Choices interact across time |
| "Maximum profit with unlimited transactions" | ✅ | Buy at every local minimum, sell at every local maximum |

## Common Mistakes

| Mistake | What happens | Fix |
|---------|-------------|-----|
| Using greedy without proving | Wrong answer on edge cases | Always test with a counterexample: {1,3,4} amount 6 |
| Picking "largest" when "smallest" is optimal | Suboptimal result | Think about what choice leaves the best options for future steps |
| Not sorting before greedy | O(n²) or wrong answer | Many greedy strategies require a specific sort order |
| Confusing greedy with DP | Greedy is faster but often wrong | If greedy fails on a small example, switch to DP |

---

## The Greedy Litmus Test

Before committing to a greedy solution, ask:

1. **"Does my choice at step i constrain the choices at step i+1 in a way that could be better served by a different choice at step i?"**
2. **"Can I find a counterexample with 3–4 elements?"**
3. **"If I sort by X, does taking the first element always leave the best remaining problem?"**

If you can't answer "yes" to all three, greedy is probably wrong.

---

## Recap

- **Greedy = make the locally best choice, never look back.** O(n) or O(n log n) when it works.
- **Proof by exchange argument:** Show that replacing an optimal solution's first different choice with the greedy choice doesn't make it worse.
- **Greedy fails** when choices interact (arbitrary coin change, 0/1 knapsack). Test with small counterexamples.
- **Greedy works** when the problem has the "greedy choice property" (interval scheduling, fractional knapsack, Huffman coding, MST).
- **The danger:** Greedy is easy to implement and easy to get wrong. Always prove or test.
