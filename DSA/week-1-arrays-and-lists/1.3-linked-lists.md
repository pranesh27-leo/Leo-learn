# Linked Lists

## What is it, in one line?

A **linked list** chains **nodes** (value + pointer to next); no contiguous memory requirement.

Hello Algo **Chapter 4.2**: [Linked list](https://www.hello-algo.com/en/chapter_array_and_linkedlist/linked_list/).

---

## Why it exists

O(1) insert/delete **when you already have the node pointer**—useful for LRU caches, polynomial arithmetic, some lock-free structures.

Trade-off: no O(1) random access; extra pointer memory.

---

## Singly linked list node

```cpp
struct ListNode {
    int val;
    ListNode* next;
    ListNode(int x) : val(x), next(nullptr) {}
};
```

---

## Reverse list (LC 206) — iterative

```cpp
ListNode* reverseList(ListNode* head) {
    ListNode* prev = nullptr;
    while (head) {
        ListNode* nxt = head->next;
        head->next = prev;
        prev = head;
        head = nxt;
    }
    return prev;
}
```

O(n) time, O(1) space.

---

## Fast & slow pointers (pattern preview)

- Middle of list: slow +1, fast +2.
- Cycle detection: if fast meets slow, cycle exists.

**Real-world:** Floyd’s cycle idea appears in memory leak detection and some streaming hash algorithms.

---

## Array vs list in interviews

| Prefer array/vector | Prefer linked list |
|--------------------|--------------------|
| Index access, binary search on array | Frequent middle insert with handle |
| Cache-friendly scans | Problem explicitly gives `ListNode*` |

LeetCode often uses linked lists for **pointer manipulation** practice.
