# What Is DSA? What Is an Algorithm?

## What is it, in one line?

**Algorithms** are precise recipes to solve problems; **data structures** are the containers those recipes use so work stays fast as data grows.

---

## Why it exists

Programs must handle more users, bigger files, and stricter speed limits. Choosing the wrong structure (e.g. scanning a whole list for every lookup) makes products feel broken at scale.

**Real-world:** Google Search does not scan the entire web for every query—it uses inverted indexes (a specialized structure). Uber matches drivers using geospatial indexes and priority queues, not naive loops over every car on Earth.

---

## Algorithms are everywhere (Hello Algo Ch 1 theme)

| Domain | Algorithm idea |
|--------|----------------|
| Maps | Shortest path (Dijkstra / A*) |
| Photos | Sorting, hashing for dedup |
| Games | Pathfinding, collision detection |
| Compilers | Graphs, hash tables for symbols |
| Databases | B-trees, join algorithms |

Interview DSA is the **same ideas** in small, clear puzzles.

---

## Interview DSA vs day-to-day engineering

| Interviews | Jobs |
|------------|------|
| Single-file, time-boxed | Teams, tests, maintenance |
| Emphasis on optimal complexity | Emphasis on clarity and reliability |
| Classic patterns | Frameworks + occasional custom DS |

Still, job code uses hash maps, queues, and trees constantly—you are learning real tools.

## Common mistakes

- Jumping to LeetCode Hard without array/list fluency.
- Memorizing solutions without naming the **pattern**.
- Ignoring **edge cases** (empty input, one element, duplicates).
