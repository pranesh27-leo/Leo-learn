# How to Approach a Coding Interview

## What is it, in one line?

A timed conversation where you **clarify**, **plan**, **implement**, and **verify**—while narrating trade-offs.

---

## Why it exists

Interviewers score **problem-solving**, not typing speed. A structured approach prevents panic and missed requirements.

---

## UMPIRE-style framework (adapt freely)

| Step | Action |
|------|--------|
| **U**nderstand | Restate problem; ask about input size, duplicates, sorted?, negative numbers? |
| **M**atch | Name a pattern (hash, two pointers, …) |
| **P**lan | Examples, brute force, then optimize; state Big-O |
| **I**mplement | Clean C++; meaningful names |
| **R**eview | Walk through example; edge cases |
| **E**valuate | Final time/space complexity |

---

## Clarifying questions (always ask 2–3)

- Constraints: `n` up to 10^5? 10^6?
- Return format: index vs value? new array vs in-place?
- Can input be empty?
- Integer overflow possible? (use `long long` in C++)

---

## Example flow: Two Sum (LC 1)

1. **Understand:** pairs summing to target; exactly one solution? unsorted?
2. **Match:** need complement lookup → **hash map**.
3. **Plan:** one pass; store `value → index`; O(n) time, O(n) space.
4. **Implement** (sketch):

```cpp
vector<int> twoSum(vector<int>& nums, int target) {
    unordered_map<int, int> idx;
    for (int i = 0; i < (int)nums.size(); ++i) {
        int need = target - nums[i];
        auto it = idx.find(need);
        if (it != idx.end()) return {it->second, i};
        idx[nums[i]] = i;
    }
    return {};
}
```

5. **Review:** `[2,7,11,15], 9` → {0,1}; duplicate values handled by storing after check.

---

## Communication tips

- Think aloud; short silence OK but say “I'm considering hash vs sort…”
- Start with **brute force** if stuck, then optimize.
- If stuck 5+ min, ask for hint—better than wrong silence.

---

## Recap

- Clarify → pattern → plan → code → test → complexity.
